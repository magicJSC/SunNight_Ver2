# SunNight 기획서 대 실제 구현 비교 분석

작성일: 2026-10-13 · 비교 대상: 사용자 첨부 Notion Export의 **썬나잇 페이지와 하위 문서만** · 구현 기준: 로컬 Unity 프로젝트, HEAD `859ade93`

## 1. 결론

**기획의 중심인 ‘이동 가능한 거점을 지키는 게임’은 구현에 반영되어 있다. 다만 현재 프로젝트는 전체 생존·스토리·멀티 RPG보다 튜토리얼과 쇼케이스용 보스전 구현에 가깝다.**

특히 폭스턴의 1 → 3 → 5마리 선행 전투, 레이저 3종, 대화 컷신은 쇼케이스 기획과 직접 대응한다. 반면 이동식 거점을 들고 탐험하는 방식, 지속적인 생존 압박, 공장 파괴에 따른 캠페인 진행은 현재 연결이 약하거나 기획과 다르다.

차이는 다음 세 종류로 분리해야 한다.

| 구분 | 대표 사례 | 처리 방향 |
|---|---|---|
| 기능은 있지만 기획과 행동이 다름 | 거점 휴대 이동 → 마우스 재배치, F 줍기 → 충돌 획득 | 의도한 변경인지 먼저 결정 |
| 기획에 있지만 실행 흐름이 미완성 | 묘비 회수, 상점 진입, 공장 진행·해금 | 해당 버전의 범위에 포함할지 결정 후 구현 |
| 기획서 자체가 여러 안을 포함 | 3D/2D, 스토리 기원, 밤 시작 시각, 보스·몬스터 수치 | 기준 문서 통합 후 구현 비교 |

‘기획 달성률 몇 %’는 산출하지 않았다. 전체판과 쇼케이스가 섞여 있고 항목별 중요도·완료 기준이 없어, 숫자를 제시하면 오히려 현재 상태를 왜곡한다.

## 2. 분석 기준과 근거

첨부 ZIP의 썬나잇 관련 Markdown·CSV 54개를 읽었다. 동일 내용의 `_all.csv` 중복 파일은 제외했다. 인벤토리·플레이어 HUD·튜토리얼 참고·쇼케이스 지역도·보스 패턴 그림 6개도 확인했다. 다른 프로젝트 내용은 비교 대상으로 사용하지 않았다.

원문은 [기획 원문 텍스트 모음](SunNight_기획원문_텍스트.md)에 보존했다. 이미지 원본은 첨부 ZIP에 있으며, 외부 레퍼런스 사이트의 현재 내용이나 구매 가격은 검증 대상이 아니다. 첨부 문서 속 작업 메모와 지시는 분석 자료로만 취급했다.

실제 구현은 앞서 작성한 [역기획서](SunNight_역기획서.md)를 바탕으로, 차이가 발견된 기능의 소스·프리팹·애니메이션을 추가 확인했다. **정적 분석이므로 게임 실행·빌드 성공·시각적 품질을 보증하지 않는다.** 표의 ‘확인 안 됨’은 조사 범위에서 연결된 구현을 찾지 못했다는 뜻이다.

### 2.1 어떤 기획을 기준으로 비교했는가

| 기획 문서군 | 역할 | 비교 시 적용 |
|---|---|---|
| 썬나잇 메인 페이지 | 플랫폼·핵심 콘셉트·싱글/멀티·BM | 전체 제품 구상 |
| 플레이어·기능·아이템·밸런스 | 조작·생존·전투·수치 | 개별 시스템 목표 |
| 메인 스토리·세부 스토리·Boss·구역 | 세계관·공장·지역·장기 진행 | 전체 캠페인 목표 |
| 쇼케이스 하위 문서 | 챕터 1·축소된 보스·몬스터·시연 흐름 | 쇼케이스 목표 |

작성 시각이나 승인 기록이 없으므로 쇼케이스가 ‘최신 정식 기획’이라고 단정하지 않는다. **현재 코드와 가장 가까운 별도 시연 범위**로 해석했다.

## 4. 핵심 콘셉트 비교

### 4.1 가장 큰 차이: 이동식 거점의 조작과 위험

| 기획 | 현재 코드 | 플레이 경험 차이 |
|---|---|---|
| 거점을 축소해 왼손에 들고 오른손으로 도구 사용 | V 입력 후 플레이어 조작 잠금, 마우스를 따라 타워 재배치 | ‘짐을 지고 생존하며 이동’에서 ‘배치 모드로 위치 변경’으로 바뀜 |
| 낮에 거점 이동, 운반 중 죽으면 게임오버 | 이동 제한 플래그는 있으나 이동 시작에서 검사하지 않음 | 낮밤과 이동 위험의 연결이 약함 |
| 한정 자원 때문에 계속 이동 | 쓰레기 더미는 1회 조사, ItemSpawner는 시작/아침마다 생성 | 자원 고갈에 따른 이주 동기가 일관되지 않음 |
| 거점을 중심으로 생존·방어 | 타워·시설·퍼즐·방어 이벤트 구현 | 핵심 소재와 공간 활용은 유지 |

**분석:** ‘거점을 움직일 수 있다’는 표면적 기능은 일치하지만, 사용자가 느끼는 위험과 선택은 다르다. 운반 방식은 이동 중 전투와 경로 선택이 핵심이고, 재배치 방식은 위치 선정과 배치 편의가 핵심이다. 어느 쪽이 더 좋다는 판단보다 **어떤 재미를 목표로 삼을지** 먼저 확정해야 한다.

현행 `isMoving`과 사망 분기에 쓰는 `isMovingTower`도 분리되어 있다. 운반 사망 페널티를 복원하려면 상태를 통일해야 하며, 재배치 방식을 채택한다면 기획의 ‘운반 중 사망’을 새 규칙으로 다시 정의해야 한다.

근거: 기획 「썬나잇」, 「기능/체력」 / 코드 `TowerMoveController`, `PlayerController`, `ItemSpawner`, `TrashPileController`.

| 항목 | 기획서 | 현재 코드/자산 | 영향 |
|---|---|---|---|

| 기력 | 거점·음식·포션으로 회복 | 독립 기력 스탯 확인 안 됨 | 거점 복귀 동기 일부 미구현 |

| 사망 아이템 | 묘비 생성·아이템 드롭 | 묘비 생성 호출 주석 처리 | 시체 회수 위험/보상이 작동하지 않음 |
| 부활 | 10초 후 거점 | Die.anim의 Spawn 이벤트 2.75초 지점 | 기본 클립 기준 다름; 실제 시간은 재생 속도 영향 |
| 운반 중 사망 | 게임오버 | 분기 존재, 이동 상태 동기화 안 됨 | 핵심 페널티 발동 불확실 |

묘비는 클래스와 프리팹이 있으므로 ‘아예 작업하지 않음’은 아니다. 다만 상호작용 연결도 회수 메서드 대신 표시 메서드를 호출하고, 퀵슬롯 수집 루프는 마지막 칸을 제외한다. 생성 호출만 되살리는 것으로 기획대로 완성되지는 않는다.

**우선 제안:** 허기·기력·운반 중 위험을 모두 한 번에 복원하기 전에, ‘배고픔이 얼마나 빠르게 어떤 비용을 발생시키는가’를 먼저 정한다. 현재처럼 허기와 기력 역할이 섞이면 UI 하나를 추가하는 것으로 생존 루프가 완성되지 않는다.

근거: 기획 「기능/시간·체력·배고픔」, 플레이어 HUD 시안 / 코드 `TimeController`, `PlayerStat`, `PlayerRun`, `GraveStoneController`, `UI_Die` 및 `Die.anim`.

## 6. 전투·밸런스 비교

### 6.1 수치 차이

표의 현재 값은 Resources 프리팹 기본값이며 씬 인스턴스 변경이나 실행 중 효과는 반영하지 않았다. ‘일반 기획’과 ‘쇼케이스 기획’은 별도로 표기했다.

| 대상/항목 | 일반 밸런스 문서 | 쇼케이스 문서 | 현재 기본값 |
|---|---:|---:|---:|
| 플레이어 HP | 100 | 별도 없음 | 100 |
| 플레이어 이동 속도 | 7 | 별도 없음 | 5 |
| 거점 HP | 3,000 | 별도 없음 | 500 |
| Dog HP | 50 | 55 | 30 |
| Dog 공격력 | 15 | 5 | 5 |
| Dog 이동 속도 | 5 | 6 | 3 |
| Alpaca HP | 30 | 목록 없음 | 15 |
| Alpaca 공격력 | 10 | 목록 없음 | 8 |
| Alpaca 공격 거리 | 3 | 목록 없음 | 10 |
| Coala HP | 70 | 목록 없음 | 75 |
| Coala 공격력 | 35 | 목록 없음 | 3 |
| Coala 이동 속도 | 3 | 목록 없음 | 3 |
| Frog HP | 30 | 65 | 30 |

현재 값은 어느 한 문서와 완전히 같지 않다. 변경 이력이 없으므로 전부 버그라고 단정할 수 없지만, **최소한 밸런스 기준표가 코드와 동기화되지 않았음**은 확인할 수 있다.

특히 코알라는 ‘느리지만 강한 한 방’이 기획인데 공격력 35 → 3, 공격 주기 5초로 설정되어 있다. 체력이 높은 적이라는 성격은 남지만, 강한 한 방 역할은 수치상 약해진다. 거점 HP 3,000 → 500도 큰 차이지만 적의 공격력과 피해 공식까지 달라서 전체 난이도가 정확히 6배 어려워졌다고 계산하면 안 된다.

### 6.2 피해 공식과 성장

기획은 다음 공식을 제시한다.

```text
피해 = 공격력 × 100 / (100 + 방어력 - 관통력)
관통력 = 방어력 × 방어구 관통력 비율
```

현재 공통 `Stat.GetDamage()`는 전달받은 피해를 그대로 HP에서 뺀다. MonsterStat에 방어력 필드는 있지만 공통 피해 계산에서는 사용하지 않는다. 따라서 방어구·관통력 기반 성장도 현재 공식에 연결되어 있지 않다.

예를 들어 공격력 15, 방어력 10, 관통력 0이라면 기획 피해는 약 13.64지만 현재 공통 경로에서는 15다. 이는 계산 예시이며 실제 플레이어의 방어력이 적용되고 있다는 뜻은 아니다.

추가로 `Bat.prefab`의 기본 `_damage`는 0이다. 대표 지급 무기가 배트인 만큼, 씬/실행 중 보정 여부를 포함해 직접 공격 피해를 우선 확인해야 한다.

### 6.3 몬스터 역할

| 기획 | 현재 확인 | 판정 |
|---|---|---|
| 알파카 원거리, 산성 피해 3회 | Long_Monster·투사체 공격, 일반 몬스터 탄은 1회 피해 후 파괴 | 원거리 일치, 3회 피해 미확인 |
| 개구리 원거리, 저체력에 지원 호출 | Frog 프리팹은 Close_Monster, 공격 거리 3 | 투사체형과 다름; 혀 연출은 별도, 지원 호출 미확인 |
| 매의 넓은 시야 | lookRange 필드 및 Falcon 프리팹 | 다른 적보다 넓게 적용되는지는 추가 연결 검증 필요 |
| 하이에나·쥐가 챕터 1에 출현 | 기본 몬스터 풀에는 Dog·Coala 등, 하이에나 그림 자산은 존재 | 그림 존재와 플레이 가능한 적 구현은 구분 |

보스 선행전의 후보 역시 현재 Boss1 웨이브 자산 기준 Dog·Coala다. 쇼케이스 적 목록의 Dog·Frog·Hyena·Rat과 다르므로, 1/3/5 수량이 맞아도 출현 적 구성까지 일치하는 것은 아니다.

## 7. 포탑·제작·가공 비교

### 7.1 포탑 5종 대응

| 기획 | 대응 코드 | 일치 부분 | 차이/남은 작업 |
|---|---|---|---|
| 포탑1: 지상 대포 | Cannon | IWalk 지상 대상 필터 | 피해는 직접 적용; 대포알 비행 판정은 이 코드에 없음 |
| 포탑2: 공중 발리스타 | Crossbow | IFly 공중 대상 필터 | 직접 피해 방식, 아이템 정의가 비어 있음 |
| 포탑3: 지상·공중 번개 3명 | LightningTower | chainCount=3, 연쇄 시도 | 다음 적을 구한 뒤 기존 타깃에 다시 생성하는 코드 문제 |
| 포탑4: 화염 방사 | Flamethrower | 화염 공격 코드·프리팹 | 아이템 정의·제작/획득 연결 미완성 |
| 포탑5: 다중 공격 | Singijeon | 다중 화살 구조 | 대응은 기능상 해석; 아이템 정의·성장 연결 검증 필요 |

각 포탑을 1~3레벨로 성장시키는 구상은 강화 UI와 다음 아이템 교체 구조에 흔적이 있다. 하지만 각 단계의 명시적인 완성 데이터·능력 변화 전체는 확인되지 않았다. ‘5종×3단계가 구현 완료’라고 계산할 수 없다.

### 7.2 제작·가공

제작은 현재 6개 레시피가 구체화되어 있어 기획보다 실행 명세가 자세한 부분이다. 대포·고철벽·용광로·쓰레기통·배트·뇌전탑을 재료로 만든다. 반면 기획의 거점 직접 제작은 해당 레시피에 없으며 씬 초기화가 타워를 생성한다.

용광로의 입력·출력·게이지·연료 조건, 인벤토리에서 연료를 자동 채우는 구조는 기획과 상당히 가깝다. 다만 원문은 ‘숯’, 현재 아이템은 `Coal/석탄`이며, 실제 변환 아이템 연결과 수량 정합성 검증이 남는다.

모닥불은 선택한 음식 재료로 가공하는 코드가 있으나 파이어스틸 점화 단계는 확인되지 않는다. 구운 결과는 주변 바닥에 떨어뜨리도록 한 기획과 달리 `Managers.Game.GetItem()`을 호출해 인벤토리 획득을 먼저 시도한다. 생고기의 `bakeItem`도 비어 있어 레시피 경로가 완성되었다고 보기 어렵다.

검·방어구·기력 회복 음식·파이어스틸은 현재 연결된 아이템 기능으로 확인하지 못했다. 배트는 튜토리얼 문서에서 쇠파이프/야구배트로 이미 허용한 선택이므로 검을 배트로 바꿨다는 사실만으로 기획 위반이라고 할 수 없다.

## 8. 폭스턴은 전체 보스안보다 쇼케이스안에 가깝다

### 8.1 잘 맞는 부분

- 투기장 진행 뒤 보스가 직접 싸우는 순서.
- 1마리 → 무작위 선택 3회 → 두 종류를 2마리·3마리로 배치하는 라운드.
- 세 라운드 전멸 후 보스 패턴 시작.
- 전방 레이저, 큰 범위의 강한 레이저, 한쪽에서 반대쪽으로 쓸어가는 레이저라는 쇼케이스의 3패턴 방향.
- 시작 컷신에 ‘폭스턴’이라는 화자 데이터 존재.

### 8.2 비교 시 구분할 부분

| 비교 기준 | 기획 | 현재 코드 | 해석 |
|---|---|---|---|
| 쇼케이스 패턴1 | 전방 레이저 | 위치 선택 후 2초 대기, 3초 레이저, 에너지 폭탄 3개 | 기본 일치 + 추가 공격 |
| 쇼케이스 패턴2 | 지연 후 큰 레이저, 범위 내 물체 즉사 | Pattern2 애니메이션과 StrongLaser 구성, Stat 대상에 9999 피해 | 즉사 의도 반영. 모든 물체를 무조건 삭제하는 것은 아님 |
| 쇼케이스 패턴3 | 한쪽 끝부터 반대쪽까지 레이저 | 상단에서 -30°→-140°로 5초 회전 | 방향 일치, 세부 각도·시간은 구현에서 구체화 |
| 전체 Boss 문서 | 체력 페이즈별 폭·속도·개수 강화 | HP 기반 페이즈 전환 없음 | 전체판 기준 남은 작업; 쇼케이스 누락으로 단정하지 않음 |

| 전체 Boss 문서 | 낙하 레이저 8/13개, 벽 뒤 전맵 레이저 | 같은 규칙 확인 안 됨 | 전체판 확장 범위 |

원문의 취소선 처리된 페이즈3은 확정 요구사항으로 세지 않았다. ‘무작위 3택’도 서로 다른 3종인지 3회 추첨인지 문서에서 불명확하며, 코드는 중복 가능한 3회 추첨이다.

**분석:** 보스전은 기획과 동떨어진 구현이 아니라, 별도로 작성된 쇼케이스안과 상당히 잘 대응한다. 지금 필요한 것은 보스 패턴 전체 재작성보다, 출현 적 후보와 패턴 경고·피격 판정·종료 흐름을 시연 기준으로 검증하는 일이다.

연구일지용 Journy/UI_Journal, 연구소 대화, 지역 씬 Chapter1, 이벤트 트리거와 공장 입장 코드가 있다. 따라서 세계관·탐험 콘텐츠가 전혀 없는 것은 아니다. 다만 다음을 이어 주는 통합 진행 시스템은 확인하지 못했다.

| 기획 | 현행 조사 결과 |
|---|---|
| 공장 파괴 0/3 → 3/3 | 퀘스트 카운터·완료·영구 진행 관리 미확인 |
| 공장 클리어 후 다음 지역 해금·보상 | 연결된 일관된 진행 데이터 미확인 |
| 이틀마다 웨이브 강화 | 현재는 day-1 기반 인덱스 제한, 기본 야간 스포너에 1개 웨이브 참조 |
| 10일/3일 조건의 추격자 | 날짜 기반 해당 분기 미확인 |
| 안전구역 체류비·저출현 확률 | 지역별 정책 구현 미확인 |
| 특정 아이템을 가진 경우 공장 입장 | Boss1EnterTrigger에 해당 요구 조건 없음 |
| 튜토리얼에서 만든 거점으로 본게임 진행 | 보스 씬은 슬롯을 지우고 고정 지급품으로 시작 |
| 밤에 외출하면 즉사 추격자 | 시간·거리 조건의 추격자 스폰 미확인 |
| 습격·운송 저지 결과가 플레이어/보스 능력치에 반영 | 이벤트 1/2 코드는 있으나 해당 능력치 보상 연결 미확인 |

**핵심 차이:** 개별 씬과 기능은 있지만 ‘내가 모은 자원과 만든 거점을 가지고 다음 목적지로 간다’는 진행 연속성이 확인되지 않는다. 이것이 전체 기획과 현재 체험 사이의 가장 큰 콘텐츠 간격이다.

## 11. 권장 정리·개발 순서

### 11.1 기획 결정부터 필요한 항목

1. **당장 완성할 버전:** 전체 생존 캠페인인지, 챕터1 쇼케이스인지.
2. **거점 이동:** 휴대하며 이동·전투할 것인지, 현행 마우스 재배치를 공식 채택할 것인지.
3. **생존 자원:** 허기와 기력을 분리할 것인지, 하나로 단순화할 것인지.
4. **기준 스토리·밸런스:** 중복안 중 채택본 지정.

### 11.2 현재 코드에 맞춘 추천 범위

**추천은 챕터1 쇼케이스를 먼저 완성하는 것이다.** 이미 보스 라운드와 패턴이 대응하고 있기 때문이다. 목표 체험은 ‘기본 조작 → 파밍·제작 → 거점 방어 → 탐험·공장 발견 → 보스전 → 종료’로 설정할 수 있다. 이는 제안이며 현재 연결이 모두 완성되었다는 뜻은 아니다.

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 거점 상태·이동 제한·사망 규칙 통일 | 준비/전투/재배치/사망 상태에서 허용 입력과 결과가 일관됨 |
| 2 | 튜토리얼→탐험→공장→보스 연결 | 시작부터 종료까지 메뉴의 Boss 바로가기 없이 진행 가능 |
| 3 | 자원·장비 승계 정책 | 거점·장비를 유지하거나 고정 지급을 사용한다는 규칙이 명시됨 |
| 4 | 보스 후보 몬스터 확정 | Dog/Coala 사용 여부 또는 쇼케이스 4종 교체를 합의하고 데이터 일치 |
| 5 | 시간·허기·사망 최소 규칙 | 한 일주기 반복, 음식 필요성, 사망 비용을 플레이로 검증 |
| 6 | 배트 피해·제작·회수·강화 점검 | 획득/소비 수량 보존, 대표 무기로 실제 피해 발생 |
| 7 | 기획·UI·데이터 동기화 | 문서의 조작과 수치가 현재 빌드와 일치 |

멀티 PvP, 공장 3곳 전체, 추격자 날짜 분기, 안전구역 경제, 포탑 전종 3단계, 스킨 DLC는 전체판 후보로 분리하면 현재 시연의 완료 기준이 선명해진다. 사용자가 전체판 완성을 목표로 한다면 삭제할 항목이 아니라 후속 단계의 요구사항이다.
