# SunNight 씬 전환·저장 복원·종료 검증 v0.3

2026-10-29 · `feature/level-design` · Unity 6000.5.10f1

이 기록은 [첫밤 이후 탐색·보스 검증](SunNight_첫밤이후탐색보스검증_v0.3.md)에 남겨 두었던 DOTween 런타임 경고와 Play Mode 종료 시 `@Managers`·`@SoundRoot` 재생성 오류의 후속 수정이다. 밸런스 수치와 저장 형식은 변경하지 않았다.

## 원인과 수정

- **지붕·벽 투명도:** `InsideBuildTrigger`의 가상 색상 트윈이 씬 파괴 후에도 타일맵을 갱신했다. `VisibleTile_Wall`에도 같은 구조가 있었다. 오브젝트마다 트윈을 보관하고 진입·이탈 방향이 바뀌면 이전 트윈을 취소한다. 비활성화 시 소유 트윈을 종료하고, 파괴된 타일맵에는 값을 쓰지 않는다.
- **카메라·연출·UI:** 카메라 흔들림, Timeline의 위치 이동, 보스 HP 등장 효과, 도움말 확대 효과를 대상의 수명과 연결했다. 비활성화 시 완료 콜백을 강제로 실행하지 않고 취소한다. 보스 HP 이벤트는 UI 파괴 시 구독 해제한다.
- **매니저 종료:** 정리 콜백의 `Managers.UI`·`Managers.Sound` 접근이 싱글턴 초기화를 호출해 종료 중 새 오브젝트를 만들 수 있었다. 종료 플래그와 생성하지 않는 `HasInstance` 조회를 추가했다. 종료 콜백은 기존 매니저가 있을 때만 정리하며, 새 Play Mode 진입 시 정적 수명주기 상태를 초기화한다. 사운드도 종료 중이거나 AudioSource가 파괴됐으면 재생하지 않는다.

전체 트윈을 무조건 삭제하거나 DOTween Safe Mode·경고 출력을 끄지 않았다. 각각의 소유 오브젝트에서 정리한다. API 동작은 [DOTween 공식 문서의 SetLink·Kill](https://dotween.demigiant.com/documentation.php)로 확인했다.

## 검증 방식

`Tools/LifecycleAudit.cs`를 실행 중인 Unity에서 수행한다. 자동화된 수명주기 회귀 시험으로, 사람의 게임 조작·전체 전투 재플레이는 아니다.

1. 실제 획득한 [공장 진입 전 저장](level-design/v03-postnight-final-pre-factory.json)을 정상 저장 복원 API로 읽는다.
2. 실제 컴포넌트의 진입·이탈 콜백을 빠르게 8회 반복한다. 지붕 투명도가 최종 이탈 시 1, 진입 시 0으로 도달하는지 확인한다.
3. 실제 저장 API로 파일을 쓰고, 타일맵·카메라·위치 이동 트윈이 실행 중인 상태에서 다시 읽는다.
4. 공장 진입 버튼의 실제 이벤트를 실행해 씬 전환·시설 승계를 확인한다. 플레이어를 실제 이동시켜 진입 컷신의 조작 잠금 상태를 만든 뒤 필드 저장을 다시 읽는다.
5. 자원, 슬롯, 연구·수집·경비 처치 이력, 시설 위치·개별 HP, 플레이어 HP·허기, 거점 HP, 코인을 대조한다. 필드 복원에서는 플레이어·거점 위치와 날짜·시간도 비교한다.
6. 30초짜리 위치 이동·카메라 흔들림과 열린 인벤토리가 있는 상태에서 Play Mode를 종료한다. 로그 수집은 종료까지 유지한다.

시험용 저장은 `Logs/LifecycleAudit`에만 작성한다. 사용자 기본 저장 파일을 덮어쓰지 않는다. 씬·프리팹을 저장하거나 자원·HP를 추가 지급하지 않는다.

## 구분해서 남긴 기존 경고

**2026-10-29 후속 수정:** 아래에 남겼던 현재 플레이 경로의 Missing Script 및 초기화 경고는 [초기화 경고 검증 보고서](SunNight_초기화경고검증_v0.3.md)에서 수정·재검증했다. Missing Script 14건은 튜토리얼 벽 2개의 참조가 반복 로드되며 발생한 출력이었으며, 에디터 복귀에만 한정되는 경고라는 앞선 설명은 정정한다. 후속 3개 세션의 시작·종료 및 필드↔공장 반복에서 Console 경고·오류는 0건이다. 아래 문단은 당시 검증 범위의 기록이다.

초기 Play Mode 진입/에디터 씬 복귀에는 `The referenced script (Unknown) ... is missing`과 `MonoBehaviour`를 `new`로 만드는 기존 경고가 있다. 이번 필드↔공장 반복 구간에서 발생한 DOTween 경고·매니저 종료 오류와 별개이며, 누락 컴포넌트 제거와 기존 매니저 서비스 구조 변경은 하지 않았다. 따라서 프로젝트의 모든 종류의 경고가 0개라고 주장하지 않는다.

검증 스크립트의 메모리 내 컴파일은 기존 DOTween DLL의 .NET 참조에 대한 `CS1701` 진단도 반환한다. 실행 중 발생하는 파괴된 대상 경고와 구분한다.

사용한 검증 절차: Unity CLI `playmode-verification-loop.md`, Pipeline `commands/scripts.md`·`commands/editor-lifecycle-and-observability.md`, uGUI `SKILL.md`.
